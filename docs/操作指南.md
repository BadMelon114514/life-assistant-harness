## 一、环境要求

| 组件 | 要求 |
|------|------|
| JDK | 17 及以上 |
| MySQL | 8.0（本地已部署） |
| 构建工具 | Gradle（已自带 `gradlew.bat`） |
| 浏览器 | Chrome / Edge / Firefox 等现代浏览器 |
| AI 密钥 | DeepSeek API Key（可选，未配置也能用大部分功能；默认模型 deepseek-v4-flash） |

> 系统为**本地化部署**，所有数据存储于本地 MySQL 数据库与运行目录下的 `./data` 文件夹，无需外网服务器。

## 二、首次部署（一次性）

> 以下操作只需在**第一次**运行时执行；以后再次启动跳过本步骤。

### 第 1 步：初始化数据库

在终端执行初始化脚本，创建数据库 `farming_harness` 及全部数据表：

```bash
mysql -uroot -p < src/main/resources/schema.sql
```

（提示输入密码时，输入你的 MySQL root 密码）

执行后可用以下命令确认数据库已创建：

```bash
mysql -uroot -p -e "SHOW DATABASES LIKE 'farming_harness';"
```

### 第 2 步：配置数据库连接

数据库密码通过环境变量提供，不写入配置文件（执行 `schema.sql` 与启动应用时都需要设置）：

```powershell
$env:DB_PASSWORD="你的MySQL密码"
```

需要改用户名时设置 `DB_USERNAME`；地址与端口在 `src/main/resources/application.yml` 中调整。上下文存储服务同样读取 `DB_PASSWORD`（或 `CTX_DB_PASSWORD`）。

### 第 3 步：打包

在项目根目录执行（使用本地 Maven 仓库，无需联网）：

```bash
gradlew.bat clean bootJar --offline
```

构建成功后，可执行文件为：`build/libs/farming-0.0.1-SNAPSHOT.jar`

## 三、启动与访问

### 启动系统

```bash
java -jar build/libs/farming-0.0.1-SNAPSHOT.jar
```

启动成功后，控制台会输出：

```
生活助理 Harness 启动完成，已初始化默认 Teammate 进程
```

> 系统默认启动 3 个 Teammate 进程：
> - mate-运营分析（电商运营数据分析师）
> - mate-客服响应（客服对话处理员）
> - mate-商品助理（商品信息整理助手）

### 访问系统

浏览器打开：**http://localhost:8080**

默认端口为 `8080`，如需修改请编辑 `application.yml` 中的 `server.port`。

### 界面导航

登录后左侧为功能导航栏，共 8 个页面：

| 导航 | 页面 |

| 🏠 生活助理 | 默认首页，AI 对话（支持联网搜索与技能） |
| 📊 进程监控 | 查看 Teammate 进程实时进度 |
| 📋 任务看板 | 任务创建与执行 |
| 📚 本地知识库 | 文件上传与检索 |
| 🧠 记忆库 | 长期记忆管理 |
| 🔌 MCP 服务 | 外部工具/数据服务管理 |
| 🛠️ Skill 技能 | 自定义技能指令管理 |
| ⚙️ 设置 | AI 服务、系统参数与搜索配置 |

## 四、设置页：配置 AI 服务

> 配置后即可使用「生活助理」的完整 AI 能力。**不配置也能使用**任务、监控、知识库、记忆等功能。

### 4.1 进入设置

点击左侧导航 **⚙️ 设置**。

### 4.2 填写 AI 服务配置

在「AI 服务配置」卡片中：

| 字段 | 填写说明 | 默认值 |
|------|---------|--------|
| 服务提供商 | 选择 `DeepSeek（deepseek-v4-flash）` 或 `OpenAI 兼容` | DeepSeek |
| API 服务地址 | 一般保持默认 | `https://api.deepseek.com` |
| 默认模型 | 使用的模型名称 | `deepseek-v4-flash` |
| API 密钥 | 填入你的 DeepSeek API Key | 空 |

填写完成后点击 **「保存 AI 配置」**。

配置完成后可点击 **「🔌 测试连接」** 按钮，系统会向 AI 发送一条测试消息，验证密钥与网络是否正常。若显示「✅ AI 连接成功」表示配置无误。

### 4.3 多模型管理与切换

系统支持配置**多个 AI 模型**并随时切换当前使用的模型：

1. 在「AI 服务配置」卡片下方的 **「🧩 多模型管理」** 表格中查看已配置的模型
2. 点击 **「＋ 新增模型」** 添加模型（填写显示名、提供商、服务地址、模型名、API 密钥）
3. 每个模型可 **「启用」**（切换为当前使用）、「编辑」、「删除」
4. 标记为 **「当前使用」** 的模型即 AI 实际调用的模型（互斥激活）

**聊天页快捷切换**：
- 在「🏠 生活助理」聊天区顶部有 **「🤖 模型」下拉框**
- 可直接切换当前使用的模型，无需进入设置页

> 配置的模型全部保存在系统数据库 `t_ai_model` 表，切换后立即生效，后续 AI 调用均使用激活模型。

### 4.4 AI 错误恢复（自动容错）

系统借鉴 Agent Harness 的错误恢复机制，让 AI 调用更稳定：

| 场景 | 自动处理 |
|------|---------|
| **限流（429）** | 指数退避 + 随机抖动，自动重试 |
| **服务过载（5xx）** | 自动重试；连续过载则切换备用模型 |
| **主模型故障** | 自动切换到已配置的其他模型（fallback） |
| **上下文过长** | 返回明确提示，引导开启新对话或压缩上下文 |

**配置备用模型建议**：
- 在「🧩 多模型管理」中配置 **2 个及以上**模型
- 主模型故障时，系统会自动切换到其他已配置的模型，用户无感知

### 4.3 修改/更换 API Key

- 已保存的密钥在输入框内以 `******` 掩码显示（不会泄露完整密钥）
- 如需更换，直接在「API 密钥」输入框填入**新密钥**并保存即可
- 若要清空密钥，留空保存即可

### 4.4 系统参数

「系统参数」卡片可设置：
- **系统名称**：显示在页面的系统标题
- **默认工作进程数**：默认启动的 Teammate 数量（1-20）

修改后点击 **「保存系统参数」**。

## 五、生活助理：AI 对话

> 需要先在「设置」页配置 API Key。

### 5.1 发起对话

1. 进入 **🏠 生活助理**
2. 在底部输入框输入问题，按回车或点击「发送」
3. 助手会结合**团队状态、任务进度、记忆库、知识库**给出回答

### 5.2 常用提问示例

```text
· 我们团队现在的任务进度如何？
· 帮我整理一份双十一促销活动方案
· 总结一下知识库里关于退款政策的内容
· 记住：我们店的客单价目标在 300 元以上
```

### 5.3 让助手记住信息

在对话中说出 **「记住」/「记下」/「备忘」** 等指令，助手会自动将关键信息存入记忆库，供后续对话引用。

### 5.4 自动搜集编写 Skill / MCP

> 聊天助手可自动识别需求，联网搜集资料并编写 **Skill 技能** 或 **MCP 服务** 定义，经安全扫描后支持**一键导入系统**。

**Skill 技能**（说出"skill / 技能 / 写一个技能"等，**或直接表达"需要 XX 功能/能力"**）：

```text
· 帮我写一个做竞品分析的 skill
· 生成一个商品文案生成的技能
· 帮我找一个社群运营的 skill
· 我需要一个自动获取当前时间的功能   ← 自动识别为 Skill，生成"获取当前时间"技能
· 我需要一个查询天气的功能          ← 自动识别为 Skill，生成"天气查询"技能
```

> **自适应判断**：助手是否创建 Skill/MCP 由 **LLM 根据语义自主判断**（而非硬编码关键词）。只要表达了要新增某种能力/工具/技能的意图（无论用词多自然、多口语化），都能被准确识别；普通的提问/查询/聊天请求则不会被误触发。例如"我想给我的系统装个实时汇率查询的能力"这类自然表述也能正确新增技能。

**MCP 服务**（说出"mcp / MCP"等）：

```text
· 帮我找一个文件系统的 MCP 服务
· 写一个天气查询的 MCP 定义
· 帮我搜集一个数据库访问的 mcp
```

**交互方式**：
1. 输入上述需求，助手会自动**联网搜集相关资源**并**编写定义**
2. 生成后助手展示定义内容与**安全扫描结果**
3. 若扫描通过，对话气泡底部会出现 **「✅ 一键导入这个技能/MCP」** 按钮
4. 点击按钮，系统自动导入；若内容含病毒/后门特征，会提示「⛔ 已拦截」并拒绝导入

> 生成的内容在导入前会经过**安全扫描**，识别命令执行、反弹 shell、凭据窃取等风险，危险内容一律拒绝导入。

**主动下载并新增（无需手动点击）**：
在需求中加入 **「下载 / 新增 / 增加 / 安装 / 扩展 / 装一个 / 接入」** 等词，助手会**直接下载并新增到系统**，无需再手动确认：

```text
· 增加一个库存管理技能                 → 自动生成并直接新增 Skill
· 增加自动获取当前时间 skill            → 自动生成"获取当前时间"技能并新增
· 帮我安装一个数据库访问的 MCP          → 自动生成并直接新增 MCP
· 增加一个天气查询 mcp 服务            → 自动生成并直接新增 MCP
· 帮我下载这个 skill https://xxx/skill.json   → 直接从该 URL 下载并新增
· 帮我接入一个天气查询 mcp https://xxx/mcp.json → 直接从该 URL 下载并新增
```

> 助手具备类似 **OpenClaw** 的自主工具扩展能力：识别需求 → 联网搜集 → 生成定义 → 安全扫描 → 直接新增到系统，全程无需手动操作。

**工具自动调度（Agent 调用已安装工具）**：
助手不仅能新增 Skill/MCP，还能**自动调度已安装的工具**来完成实际任务，流程类似 OpenClaw 的 Agent：
`LLM 识别需求 → 自主决策调用哪个工具 → 执行工具 → 回填结果 → 组织回答`

| 用户请求 | 助手行为 |
|---------|---------|
| "帮我查询一下手机库存"（已装库存查询 MCP） | 自动调用该 MCP 工具获取数据并回答 |
| "帮我写一段新品手机的推广文案"（已启用文案生成 Skill） | 自动应用该 Skill 技能指令生成文案 |

- **MCP 工具**：对 active 的 http/sse MCP 服务发起请求，把返回数据注入回答
- **Skill 技能**：自动应用启用的技能指令来指导处理
- 前端对话气泡中会显示「🔧 已调用 MCP 工具「xxx」」的调度日志提示

> 工具调度由 **LLM 根据语义自主判断**是否调用工具，无需硬编码关键词。

**两种新增方式**：
| 场景 | 行为 |
|------|------|
| 消息中**含 URL** | 直接从 URL 下载，安全扫描后新增 |
| 消息中**不含 URL**（但含"下载/新增"词） | 自动生成定义，安全扫描后直接新增 |

新增成功后助手会提示「✅ 已主动下载并新增 Skill/MCP「名称」到系统」，可在「🛠️ Skill 技能 / 🔌 MCP 服务」页面查看与管理。同样，危险内容会被安全扫描拦截。

### 5.5 聊天记录持久化与回滚

> 聊天助手的对话内容会**自动保存**到数据库，切换页面后再回来仍能看到之前的聊天记录。

- **自动保存**：每次对话，用户消息与助手回复都会自动持久化。
- **跨页保留**：切换到「进程监控 / 任务看板」等页面后，再回到「🏠 生活助理」，历史对话会自动恢复显示。
- **消息计数**：对话区右上角显示历史消息数量。

**上下文连续**：
- AI 在回答时会**自动携带历史对话**作为上下文，能记住之前说过的话
- 例如先告知"我叫王小明，做电商运营"，之后问"我叫什么名字"，助手能正确回答
- 上下文自动截取最近 20 条对话，避免超长

**运行过程监控**：
- 每次对话后，助手回复中会带一个 **「🔍 助手运行过程」** 的折叠面板（点击展开/收起）
- 展示助手处理该请求的**完整执行链路**，例如：
  ```
  ✅ 识别请求意图 — 普通对话
  ✅ 检索本地知识库 — 无相关文档
  ✅ 联网搜索判断 — 无需联网
  ✅ 工具调度 — 已调用内置工具「get_current_time」
  ✅ 组装系统提示词 — 完成上下文组装
  ✅ 调用 AI 生成回答 — AI 已返回结果
  ```
- 每个步骤标注状态（✅ 完成 / ⏳ 进行中 / ❌ 失败 / ⏭️ 跳过）与耗时（毫秒），方便排查助手运行情况
- 不再只是被动看到结果，能直观了解助手内部做了什么

**自验证自纠错**：
- AI 在生成回答后会自动**自验证**一次（不增加额外操作成本）
- 评估要点：是否切题、是否混淆历史对话、是否包含虚假信息、是否合理自洽
- 若发现问题是 LLM 会自动重写（**自纠错**）并保留 pSelfCorrected 标记
- 自验证/纠错结果会在「🔍 助手运行过程」面板中显示步骤与详情
- 有效减少"答非所问"的情况，特别是上下文丰富时混入历史主题的情况

**流式输出（实时思考过程）**：
- 助手回答改为**流式输出**（SSE 技术），类似 ChatGPT/DeepSeek 一样**边生成边逐字显示**
- 对话时不再只有"思考中..."然后一次性弹完整答案，而是能实时看到 AI 逐 token 输出的思考过程与最终答案
- 深层模型会先展示推理思考片段（reasoning_content），再展示最终答案（content）
- 支持随时查看生成过程，体验更流畅、更直观

**终止任务（停止按钮）**：
- 流式输出开始后，**发送栏**（输入框旁）会出现 **「⏹ 停止」** 按钮
- 点击后立即中断 AI 生成：已生成内容保留在气泡中并标记「（已由用户终止）」，同时存入聊天记录
- 适用于回答过长、跑偏或不再需要时的快速打断

**长回复自动折叠 + 总结**：
- 回复超过 **220 字**时自动折叠为卡片：顶部显示 **「📌 总结：...」**（AI 生成的要点总结，最多 10000 字，尽量完整覆盖要点），下方「展开全文」按钮
- 点击「展开全文」查看完整回复（含内嵌图表，展开后渲染）；再次点击收起
- 短回复（≤220 字）正常全文显示，不折叠

**跨页切换不丢气泡**：
- 流式输出过程中切换到其他子页面再切回，**正在输出的气泡保留**（DOM 缓存恢复），继续完成输出
- 输入框草稿、滚动位置一并保留

**子对话（多会话）管理**：
- 聊天区顶部提供**子对话切换下拉框**，可管理多个独立对话
- **「＋ 新建对话」**：创建新的子对话窗口，互不干扰
- **切换**：从下拉框选择历史子对话，自动加载对应记录与上下文
- **「🗑️ 删除当前对话」**：删除当前子对话窗口及其全部记录（不可恢复）

**回滚 / 清空对话**：
- 点击对话区右上角 **「🔄 清空/回滚」** 按钮
- 确认后清空全部聊天记录，对话区回到初始欢迎界面
- 该操作不可恢复，请谨慎使用（清空后上下文也随之重置）

### 5.6 未配置 API Key 时

- 首页顶部会显示黄色提示条「尚未配置 API Key」
- 此时仍可进入「进程监控 / 任务看板 / 知识库 / 记忆库」正常使用
- AI 调用会提示「请前往设置页面填写」

### 5.7 文件操作能力（阅读/修改项目库）

> 聊天助手可直接**阅读/修改后端项目库文件夹**（仅限项目根目录内），并支持**自行新增工具脚本**（.py/.js）。修改类操作为高危动作，**执行前必须经您确认**。

**阅读类（低危，直接执行）**：
```text
· 列出项目根目录下的文件
· 读取 build.gradle 文件内容
· 查看项目结构概览
```

**修改类（高危，需确认）**：
```text
· 在 tools 目录下新增一个 hello.py 脚本   ← 弹出确认框，确认后写入
· 删除 data/ 下的 xx.txt                   ← 弹出确认框，确认后删除
· 运行 tools/analyze.py                    ← 弹出确认框，确认后执行
```

**交互流程**：
1. 提出文件操作需求 → 助手识别为修改类操作
2. 前端弹出 **「⚠️ 高危操作确认」** 框，展示操作类型、目标路径、参数/内容
3. 点击「✅ 确认执行」才真正执行；点击「取消」则不执行
4. 执行结果（写入/删除/脚本输出）追加到对话气泡中

**安全约束**：
- 所有路径解析后必须位于项目根目录（`d:/jvav/farming`）内，`../` 越界访问一律拒绝
- 读取文件限制 200KB 以内
- 脚本执行仅支持 `.py` / `.js`，60 秒超时自动终止

### 5.8 数据分析与图表生成

> 助手内置 **pandas 风格数据分析引擎**，可对知识库文档中的表格数据（Markdown 表格 / CSV / JSON 数组）做统计分析并**生成图表**（柱状图/折线图/饼图）。

**用法示例**：
```text
· 用个人消费电子报告做数据统计并生成图表   → 分析 + 柱状图
· 分析家用车报告的品类出货量排行并生成柱状图 → topN + 图表
· 做一份趋势分析并画折线图                → trend + 折线图
· 统计各品类占比并生成饼图                → distribution + 饼图
```

**支持的分析类型**：

| 请求关键词 | 操作 | 图表 |
|-----------|------|------|
| 统计 / 描述 | describe（count/mean/min/max/sum/std/中位数） | 柱状图 |
| 排行 / Top N | top（按数值列排序取前 N） | 柱状图 |
| 趋势 / 走势 | trend（随维度变化） | 折线图 |
| 占比 / 分布 | distribution（分类汇总） | 饼图 |

**图表渲染**：分析结果以 **ECharts 图表**直接渲染在对话气泡中（柱状/折线/饼图），无需跳转。数据源自知识库文档中的数值表格，数值可含"约6.9亿部 / +3.2% / 3400元"等带单位格式（自动提取数字）。

### 5.9 内置工具自动调度

> 助手内置一组**开箱即用的工具**，LLM 会根据语义自动决定是否调用（无需关键词触发），支持一次调度多个工具。

| 内置工具 | 用途 | 示例请求 |
|---------|------|---------|
| `get_weather` | 真实天气（按**用户所在城市**查询，自动定位） | "获取天气" |
| `get_hot_topics` | 今日热点 / 热搜资讯（联网检索） | "今日热点" |
| `analyze_data` | 知识库数据分析 + 图表 | "分析报告数据并生成图表" |
| `get_current_time/date/...` | 时间 / 日期 / 星期 / 时间戳 | "现在几点了" |
| `get_system_status` | 系统状态（CPU/内存） | "系统状态如何" |
| `describe_workspace` / `list_dir` / `read_file` | 项目文件阅读 | "读取 build.gradle" |
| `write_file` / `delete_file` / `run_script` / `mkdir` | 项目文件修改（需确认） | "新增一个脚本" |
| `run_cli` | 低风险命令行工具（白名单只读命令） | "查看本机 IP 配置" |
| `dispatch_teammates` | 多 Agent 协同调度（拆解子任务） | "帮我同时做三件事…" |
| `import_library` | 内置库导入（技能/MCP） | "导入内置技能库" |

**天气按用户定位**：发送"获取天气"时，浏览器自动定位（Geolocation 优先 + IP 定位多服务兜底）附加用户所在城市，返回**本机位置**的天气（而非服务器部署位置）。定位失败时降级为服务器 IP 天气。

### 5.10 多 Agent 协同调度

> 当用户**同时提出多项任务**或需要**多个角色分工协作**时，助手会自动触发多 Agent 调度：将请求拆解为多个子任务，派发给后台 Teammate 守护进程并行执行，并创建任务看板条目。

**触发方式**：在聊天框输入包含多任务意图的自然语言，例如：

- "帮我同时做三件事：查今天北京天气、整理本周热点、分析知识库数据生成图表"
- "让日程助理规划明天行程，让资讯助手搜集 AI 动态，让数据助手分析知识库文档"
- "分头行动：查天气、写周报、分析数据，全部完成"

**执行流程**：
1. 助手识别多任务意图（含"同时/分工/协同/分别/让…让…"等关键词，或包含 2 个以上动作词）
2. LLM 将请求拆解为子任务 JSON（title / description / owner / blockedBy）
3. 每个子任务创建为 `HarnessTask` 进入任务看板，分配给指定（或自动分配）的 Teammate
4. 后台 Teammate 守护线程自动认领并逐步执行，进度可在「进程监控」「任务看板」实时查看

**提示**：若 LLM 未返回拆解结果，系统会自动按动作词回退拆解，保证多任务请求一定产生子任务。

### 5.11 低风险命令行工具

> 助手可执行**低风险只读命令**（`run_cli`），采用**白名单机制**，参数禁止 shell 元字符，从根上防止注入。

**默认白名单命令**：
`ipconfig` / `ping` / `netstat` / `systeminfo` / `tasklist` / `whoami` / `ver` / `hostname` / `date` / `time` / `echo` / `dir` / `path` / `vol` / `nslookup` / `tracert` / `sc query` / `driverquery`

**使用示例**：
- "查看本机 IP 配置" → 执行 `ipconfig`
- "查一下系统信息" → 执行 `systeminfo`
- "ping 一下本地网络" → 执行 `ping -n 3 127.0.0.1`

**安全规则**：
- 命令必须在白名单内，否则拒绝执行
- 参数禁止包含 `& | ; > < $ \` \n \r && ||` 等 shell 元字符
- 危险命令（如 `del` / `format` / `shutdown`）一律拒绝
- 白名单可**在线扩展**：见 [15.2 扩展低风险命令白名单](#152-扩展低风险命令白名单)

> 对应任务图机制（s12）。把大目标拆成小任务，Teammate 会自动认领执行。

进入 **📋 任务看板**，任务按三列展示：
- **待执行**：尚未开始

## 十、MCP 服务管理

> MCP（Model Context Protocol）服务用于接入外部工具/数据源，扩展系统能力。系统提供**独立管理页面**，可自行添加、测试、启停服务。

### 10.1 进入页面

点击左侧导航 **🔌 MCP 服务**。

### 10.2 新增服务

点击右上角 **「＋ 新增服务」**，填写：

| 字段 | 说明 |
|------|------|
| 服务名称 | 唯一标识，如「文件系统服务」 |
| 服务类型 | `http` / `sse` / `stdio` |
| 服务地址/命令 | http 填 URL（如 `http://localhost:9000`）；stdio 填启动命令（如 `npx -y @modelcontextprotocol/server-filesystem ./data`） |
| 功能说明 | 该服务提供什么能力 |
| 配置参数（JSON） | 可选，扩展配置 |

点击「保存」。

### 10.3 测试与启停

- **测试**：点击「测试」按钮验证服务连通性。HTTP/SSE 服务通过 HTTP 探测，成功会显示「连接成功」，并自动标记为 active。
- **启用/停用**：切换服务在线状态。
- **编辑/删除**：修改或移除服务。

### 10.4 从 URL 下载导入（自动安全扫描）

> 可从远程地址一键下载 MCP 服务配置，系统会**自动扫描病毒/后门**，安全内容才会导入。

1. 点击 **「⬇️ 从 URL 导入」**
2. 粘贴 MCP 配置的远程地址（JSON，包含 `name` / `serverType` / `endpoint` 等字段；也可为纯文本端点）
3. 点击「下载并扫描」：系统自动下载 → 安全扫描 → 导入

**扫描结果处理**：
- 扫描为**安全**：自动导入并提示「✅ MCP 已下载并通过安全扫描」
- 检测到**风险/危险**内容：**拒绝导入**，提示「⛔ 已阻止导入：N 项风险」

> 安全扫描覆盖：命令执行（Runtime.exec / ProcessBuilder）、下载执行、反弹 shell、PowerShell 混淆、Base64 编码、敏感路径访问、内网 IP、凭据窃取、持久化后门、数据外传等特征。**高危项（命令执行/反弹shell/凭据窃取等）一律拦截。**

### 10.5 从内置库导入（一键）

> 系统内置了 openclaw 生态精选的 **21 个常用 MCP 服务器**：filesystem / fetch / memory / sequential-thinking / github / context7 / playwright / time / git，以及 brave-search / gitlab / google-maps / postgres / sqlite / sentry / slack / everart / redis / notion / youtube / **reminder（定时提醒，系统内置端点）**。点击即可一键导入（已存在的条目自动跳过，不会重复）。

1. 点击 **「📦 从内置库导入」**
2. 系统自动导入内置 MCP 服务器定义（默认**停用**状态）
3. 导入后逐条「测试 + 启用」，即可在 AI 对话中被调度

**内置库文件**：`src/main/resources/openclaw/mcp.json`（可自行增删条目后重新打包）

### 10.6 定时提醒功能

> 系统内置**定时提醒**能力（对话中可直接说"X 分钟后提醒我……"），底层是本地自托管端点 `POST /api/assistant/schedule`，可作为 **http 类型 MCP**（内置库 `reminder`）接入并调度。

| 端点 | 说明 |
|------|------|
| `POST /api/assistant/schedule` | 设定提醒：`{instruct: 提醒内容(必填), delayMinutes: 延迟分钟, title: 标题, session: 会话}`；传 `cancelId` 可取消提醒（MCP 工具调用形态） |
| `GET /api/assistant/schedule` | 查询提醒列表（可带 `?session=` 过滤） |
| `DELETE /api/assistant/schedule/{id}` | 取消指定提醒 |

**触发机制**：应用启动自动建表 `t_reminder`；后台每 10 秒轮询到期提醒——先写入对应会话的**聊天历史**（浏览器离线也不丢），再经 WebSocket 推送 `assistant_notify`，聊天页自动出现 ⏰ 提醒气泡。

**对话触发方式**：助手回复中携带 `[[SCHEDULE:instruct=...;delayMinutes=...;title=...]]` 标记时，前端自动调 `POST /api/assistant/schedule` 入队；启用了 `reminder` MCP 时，助手也可直接经工具调度创建。

### 10.7 本机时间与地理位置（local-geo）

> 系统内置**本机时间 + 定位**能力（对话中直接问"现在几点了？我在哪个城市？"即可自动获取），底层是本地自托管端点 `GET /api/assistant/location`，可作为 **http 类型 MCP**（内置库 `local-geo`）接入并调度。

| 项目 | 说明 |
|------|------|
| 本机时间 | 服务器当前时间：日期 / 星期 / 时区 / 时间戳，无需外部服务，即时返回 |
| 地理位置 | 经公网 IP 定位城市/区域/国家/坐标（ipapi.co → ipinfo.io → ip-api.com 多服务级联，与前端定位策略一致）；全部不可达时优雅降级，仅返回时间并附定位失败说明 |
| 调度方式 | 启用 `local-geo` MCP 后，对话询问"本机时间 / 我在哪里 / 当前城市 / 获取定位 / 地理位置"等会**自动直调**该 MCP（无需 LLM 决策），返回真实时间与定位 |

**端点**：`GET /api/assistant/location` → `{success, time: {localTime, date, timeText, weekday, timezone, timestamp}, location: {provider, ip, city, region, country, latitude, longitude}}`

## 十一、Skill 技能管理

> Skill 技能是可注入 AI 对话的**专家指令**。系统提供**独立管理页面**，可自行添加技能，启用后助手会遵循对应指令处理任务。

### 11.1 进入页面

点击左侧导航 **🛠️ Skill 技能**。

### 11.2 新增技能

点击 **「＋ 新增技能」**，填写：

| 字段 | 说明 |
|------|------|
| 技能名称 | 如「商品文案生成」 |
| 分类 | 如「内容创作 / 运营分析」 |
| 启用状态 | 是否立即启用 |
| 技能说明 | 简要说明作用 |
| 指令内容 | 具体的处理步骤与要求，AI 会遵循执行 |

保存后，启用的技能会自动注入后续 AI 对话。

### 11.3 管理技能

- **启用/停用**：只有启用状态（已启用）的技能才会被注入对话。
- **编辑/删除**：修改指令或移除技能。

> 系统已内置「商品文案生成」「竞品分析」两个示例技能，可直接使用或修改。

### 11.4 从 URL 下载导入（自动安全扫描）

> 可从远程地址一键下载 Skill 技能定义，系统会**自动扫描病毒/后门**，安全内容才会导入。

1. 点击 **「⬇️ 从 URL 导入」**
2. 粘贴技能定义的远程地址（JSON，包含 `name` / `category` / `description` / `content` 字段）
3. 点击「下载并扫描」：系统自动下载 → 安全扫描 → 导入

**扫描结果处理**：
- 扫描为**安全**：自动导入并提示「✅ Skill 已下载并通过安全扫描」
- 检测到**风险/危险**内容：**拒绝导入**，提示「⛔ 已阻止导入：N 项风险」

> 技能指令中若包含命令执行、下载脚本、数据窃取等恶意特征，会被安全扫描识别并拦截，防止恶意技能注入系统。
> 除代码特征扫描外，系统还有**内容合规审查**：请求自动生成/新增的 Skill 或 MCP 若涉及脏话、色情、暴力、诈骗、违法、仇恨等不当内容，会直接拒绝生成（如「内容不合规：请求涉及不当内容（脏话），已拒绝生成」）。

### 11.5 从 ClawHub 技能市场查找安装

> 新增 Skill 时，系统会**优先从 ClawHub 技能市场**（https://clawhub.ai）搜索现成技能，匹配成功则直接安装；匹配不到才由 LLM 自行编写。

**触发方式**：在对话中表达"新增 / 安装 / 找一个 XX 技能"等需求：

```text
· 新增一个翻译技能
· 找一个 markdown 转 pdf 的 skill
· 安装一个数据分析技能
```

**相关校验（防"驴唇不对马嘴"）**：
- ClawHub 搜索结果会经 **LLM 相关性挑选**（失败回退关键词打分），只有与需求真正匹配的技能才安装
- 全部不匹配时降级为 LLM 生成对口技能，避免装错（如要"热点"却装成"邮件助手"）
- 安装前仍会执行**安全扫描**，危险内容拒绝

**手动搜索**：也可直接访问 `GET /api/clawhub/search?q=关键词` 查看技能市场搜索结果。

### 11.6 从内置库导入（一键）

> 系统内置了 openclaw 生态精选的 **21 个技能**：weather / github / summarize / session-logs / taskflow / spotify-player / diagram-maker / healthcheck / blogwatcher，以及 weekly-report / meeting-notes / ppt-outline / excel-formula / promotion-plan / customer-service / product-seo / review-reply / data-cleaning / sql-helper / decision-matrix / interview-prep。点击即可一键导入（已存在的条目自动跳过，不会重复）。

1. 点击 **「📦 从内置库导入」**
2. 系统自动导入内置技能（默认**停用**状态，避免未启用就影响对话）
3. 导入后逐条「启用」，即可注入 AI 对话

**内置库文件**：`src/main/resources/openclaw/skills.json`（可自行增删条目后重新打包）

> 也可直接对助手说「**帮我导入内置技能库和 MCP 服务**」，助手会自动执行导入。

## 十三、工具策略：allow/deny 白名单

> 借鉴 OpenClaw 的 tool-policy，可对助手的内置工具（天气/热点/数据分析/时间/文件操作等）和 MCP 工具设置 **允许/禁用** 白名单，用于生产环境安全管控（如禁止文件修改类工具）。

### 13.1 配置方式

进入 **⚙️ 设置** → 新增配置项（key/value）：

| 配置项 | 值 | 作用 |
|--------|-----|------|
| `tool_policy_deny` | `get_weather, file_*` | **禁用**列表（逗号分隔） |
| `tool_policy_allow` | `get_current_time, get_weather` | **白名单**：非空时仅允许列表内工具 |

**支持的通配写法**：
```text
get_weather        精确工具名
file_*             前缀通配（file_ 开头的文件操作工具）
analyze_*          数据分析类工具
*                  所有工具
```

### 13.2 规则

- 工具名命中 `tool_policy_deny` → **禁用**，助手会如实告知"该工具已被系统策略禁用"
- 若配置了 `tool_policy_allow`（非空），则**仅允许列表内**的工具，其余全部禁用（更严格）
- 未配置任何策略时：所有工具可用（默认）
- 配置**即时生效**，无需重启

### 13.3 应用示例

```text
· 生产环境禁止一切文件修改：tool_policy_deny = write_file, delete_file, run_script, mkdir
· 只允许天气与时间工具：tool_policy_allow = get_weather, get_current_time, get_hot_topics
· 完全禁用数据分析：tool_policy_deny = analyze_data
```

> 安全提示：工具策略是**第一道防线**（配置级拦截）；文件操作等修改类工具即使未被禁用，仍会弹「高危操作确认」框（第二道防线），双重保护。

## 十四、运维与常见问题

### 14.1 停止系统

方式一：在启动系统的终端按 `Ctrl + C`。

方式二（推荐）：在前端**设置页 → 危险操作 → 关闭后端服务**，或点击侧栏底部的电源按钮，二次确认后系统会优雅停机，并联动关闭上下文存储服务（8765）。页面会切换为「服务已关闭」离线页，数据不会丢失；重新启动时双击桌面的「生活助理 Harness」快捷方式即可。

### 14.2 数据存储位置

| 数据类型 | 位置 |
|----------|------|
| 数据库数据 | MySQL 的 `farming_harness` 库 |
| 知识库文件 | 运行目录 `./data/knowledge/` |
| 记忆/任务/日志 | MySQL 数据表 |

备份时，将上述位置一并备份即可。

### 14.3 常见问题排查

| 现象 | 原因 | 解决方法 |
|------|------|----------|
| 启动报「数据库不存在」 | 未执行 schema.sql | 执行 `mysql -uroot -p < src/main/resources/schema.sql` |
| 启动报「Access denied」 | 数据库密码错误 | 检查环境变量 `DB_PASSWORD` 是否正确 |
| 首页提示「尚未配置 API Key」 | 未配置 AI 密钥 | 前往「设置」页填写 |
| 对话提示「AI 调用失败」 | 密钥无效或网络问题 | 检查 Key、网络，确认模型名正确 |
| 知识库文件「解析中」长时间不变 | 大文件处理中 | 稍等片刻；超大文件请拆分 |
| 监控页显示「已断开」 | 网络中断 | 系统会自动重连（3 秒后重试） |
| 天气返回的是部署机（郑州）而非本机 | 前端定位失败（IP 定位服务不可达） | 刷新页面（Ctrl+F5）；确认浏览器允许定位；定位服务多级兜底会自动切换 |
| 工具被禁用（提示"系统策略禁用"） | 配置了 `tool_policy_deny`/`tool_policy_allow` | 前往设置页调整工具策略配置 |
| 一键导入技能按钮无反应 | 浏览器缓存旧版前端 | 强制刷新（Ctrl+F5）；若仍失败查看控制台具体报错 |
| 数据分析未生成图表 | LLM 未输出图表容器（偶发） | 系统已内置兜底：自动从工具结果注入图表容器；重试一次即可 |
| 长回复总结显示"无法提供" | 模型偶尔不遵守摘要指令 | 前端已自动降级为正文首段摘要，无需处理 |

### 14.4 端口占用

默认端口 `8080` 被占用时，修改 `application.yml`：

```yaml
server:
  port: 8081
```

保存后重新打包运行。

## 十五、扩展与二次开发

> 系统为开发者**保留了可扩展端口**，在不修改源码的前提下，可安全地扩展命令白名单、内置技能/MCP 库，并可通过 REST API 查看系统能力清单。

### 15.1 扩展端口 /api/extensions

`/api/extensions` 是系统的**可扩展性端口**，面向开发者/管理员，提供能力查看与扩展注册功能：

**查看能力清单**（GET）：
```bash
curl http://127.0.0.1:8080/api/extensions
```

返回 JSON 包含：
- `cliAllowlist`：当前生效的低风险命令白名单（默认集 + 扩展集）
- `builtinLibrary`：内置技能/MCP 库资源位置与导入 API
- `builtinTools`：全部内置工具及用途说明
- `toolPolicy`：当前工具策略（allow/deny 配置）

**扩展命令白名单**（POST）：
```bash
curl -X POST http://127.0.0.1:8080/api/extensions/cli-allowlist \
  -H "Content-Type: application/json" \
  -d '{"commands":"git status, git log, reg query"}'
```

> 执行后，新增命令立即加入 `run_cli` 白名单并持久化到设置 `cli.allowlist`，无需重启。

### 15.2 扩展低风险命令白名单

**方式一：REST 接口**（推荐，即时生效）
```bash
curl -X POST http://127.0.0.1:8080/api/extensions/cli-allowlist \
  -H "Content-Type: application/json" -d '{"commands":"your-cmd1, your-cmd2"}'
```

**方式二：设置页配置**
在「设置 → 系统参数」新增键 `cli.allowlist`，值为逗号分隔的命令列表（如 `git status, git log`）。

**安全要求**：扩展的命令应仅限**只读/诊断类**。危险命令（`del` / `format` / `shutdown` / 含 shell 元字符的命令）即使加入也会在 `runCli` 的 shell 元字符校验中被拦截。

### 15.3 扩展内置库（技能/MCP）

内置库位于项目资源目录，可直接编辑后重新打包：

| 文件 | 内容 | 字段 |
|------|------|------|
| `src/main/resources/openclaw/skills.json` | 内置技能库 | `name` / `category` / `description` / `content` |
| `src/main/resources/openclaw/mcp.json` | 内置 MCP 服务器库 | `name` / `serverType` / `endpoint` / `description` |

**添加技能**：在 `skills.json` 的 `skills` 数组追加一项，重新 `gradlew.bat bootJar` 后重启，即可在前端「📦 从内置库导入」看到新技能。

**添加 MCP**：在 `mcp.json` 的 `servers` 数组追加一项，同样重新打包即可。

### 15.4 扩展内置工具

内置工具定义于 `ToolScheduler`（`src/main/java/com/badmelon/farming/service/ToolScheduler.java`）：

| 工具 | 实现位置 | 扩展要点 |
|------|---------|---------|
| 基础工具（天气/热点/时间等） | `invokeBuiltin` | 按 `name` 关键词匹配，追加分支即可 |
| 文件类工具 | `tryFileOperation` | 需在 `BuiltinOutcome` 中声明 op 与是否需要确认 |
| 低风险命令 | `FileOpsService.runCli` | 通过 15.2 白名单扩展，无需改代码 |
| 多 Agent 调度 | `dispatchTeammates` / `decomposeByRules` | 拆解规则可定制 |
| 内置库导入 | `OpenclawImportService` | 扩展资源 JSON 即可 |

**新增一个内置工具的步骤**：
1. 在 `buildDecisionPrompt` 中声明工具名称、参数、适用场景
2. 在 `invokeBuiltin`（无参工具）或 `tryFileOperation`（带参/需确认工具）中新增分支
3. 如需配置化开关，在 `isToolAllowed` 支持的工具集中加入工具名

**工具策略配置**：通过设置键 `tool_policy_deny` / `tool_policy_allow` 可禁用/放行具体工具（见第十三章）。

### 15.5 ReAct 循环与工具去重（实现约束）

`ToolScheduler.runAgentLoop` 采用「决策 → 执行 → 观察」循环，最多 3 轮，实现上有以下约束，扩展工具时需遵守：

| 约束 | 说明 |
|------|------|
| 观察回填 | 上一轮工具结果会作为 `agentContext` 送入下一轮决策（截断 6000 字），禁止再用「本轮输入完全相同」的旧式循环 |
| 继续条件 | 仅当用户消息含顺序词（然后/接着/最后/同时/顺便…）或上一轮结果含失败信号（调用失败/不可用/超时/未找到…）才进入下一轮，避免单步请求多付一次模型调用 |
| 工具去重 | 去重键为「工具名 + 关键参数」签名：同一工具读取不同文件/不同参数不会被误拦；完全相同调用在下一轮跳过，避免副作用重复 |
| 工具匹配 | MCP / Skill 仅按名称精确匹配，找不到时返回可用清单交给模型解释，不再回退到列表第一个服务 |
| 答案权威 | 有工具结果时，`AssistantService.selfVerify` 以工具返回为事实依据；若质检把真实数据改写为「无法获取」，会被拒绝回退守卫拦截 |
| 天气城市 | 用户原话中的城市优先（惰性正则，如「北京今天天气」→ 北京），其次用【用户当前所在城市：XX】标签，避免贪婪吞掉时间词 |
| 知识库路由 | 消息含 .md/.txt 等文件名但知识库无同名文档时，不读取任意文档，交回文件工具读取工作区文件（如 README.md、docs/操作指南.md） |

- 手机与电脑连同一 Wi-Fi，打开 App →「更多 → 设置 → 服务器地址」，填 `http://<电脑局域网IP>:8080`（如 `http://192.168.1.10:8080`），点「测试连接」显示毫秒数即成功。
- 安卓模拟器无需配置，默认 `http://10.0.2.2:8080` 即宿主机。
- 连不上时检查：Windows 防火墙是否放行 8080、手机与电脑是否同网段、电脑是否处于休眠。

## 十七、iOS 客户端

项目另附原生 iOS App（`ios/`，Swift 5 + SwiftUI，iOS 16+），页面与安卓端一一对应，连同一台电脑上的后端。**iOS 工程必须在 macOS + Xcode 中构建，Windows 只能查看源码与做静态校验。**

### 17.1 环境与构建

1. 需要 macOS 13+ 与 Xcode 15+（真机还需 Apple ID 签名 Team）。
2. 打开工程：

   ```bash
   open ios/LifeAssistant.xcodeproj
   ```

3. 选择 `LifeAssistant` target → Signing & Capabilities 选择 Team → 选择模拟器（如 iPhone 16）→ Run。
4. 或命令行构建模拟器版本：

   ```bash
   xcodebuild -project ios/LifeAssistant.xcodeproj -scheme LifeAssistant \
     -configuration Debug -sdk iphonesimulator \
     -destination 'platform=iOS Simulator,name=iPhone 16' build
   ```

### 17.2 连接后端

- 电脑端先启动（桌面快捷方式或 `dist\生活助理Harness一键启动.exe`），确认 `http://127.0.0.1:8080` 可打开。
- iOS 模拟器与电脑共享网络，默认地址 `http://127.0.0.1:8080` 即可（注意与安卓模拟器的 `10.0.2.2` 不同）。
- 真机：手机与电脑连同一 Wi-Fi → App「更多 → 设置 → 服务器地址」填 `http://<电脑局域网IP>:8080`（如 `http://192.168.1.10:8080`）→「保存并测试」显示毫秒数即成功。
- 连不上时检查：Windows 防火墙是否放行 8080、是否同一网段（访客 Wi-Fi/AP 隔离不行）、电脑是否休眠、后端是否被「关闭后端服务」停掉。

### 17.3 功能对照

| 页面 | 能力 |

| 任务 | 筛选、新建、认领、+10% 推进、完成、删除 |

### 17.4 已知限制

- Windows 无 Swift/Xcode，不能在本机构建/签名/运行；仓库提供 `../tools/scripts/verify_ios_project.py` 做 143 项静态校验（工程结构、pbxproj 引用、Scheme、Info.plist、Swift 语法树等），但不能替代真实编译。
