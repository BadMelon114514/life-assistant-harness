# 上下文存储方案（类 OpenViking，Python + MySQL）

> 面向长期运行 AI 助手的上下文存储：三级冷热存储、调用权重驱动的常驻/下沉、Git 式快照与回滚、多 Agent 黑板、MCP/Skill 版本化、文档分章摘要检索。服务独立运行，通过 HTTP/MCP 与 Java 助手集成。

## 一、设计目标（对应需求）

| 需求 | 实现 |
|------|------|
| ① 三级存储（缓存/内存/外存），按冷热分级，冷数据逐级下沉，控制送入模型的数据量 | 每条上下文有 `layer`：L1（缓存/热，最近+高频）、L2（内存/温）、L3（外存/冷）。`sink()` 按桶容量把溢出条目逐级下沉：`l1_cap`（默认 40 条）外→L2，`l2_cap`（默认 200 条）外→L3。`load(budget)` 只返回 L1+L2 且总字符数 ≤ budget（默认 6000），`include_cold=True` 才带 L3。 |
| ② 按调用次数算权重，高频常驻、低频加速下沉 | `access_count` 每次 `load`/显式 `promote` 递增；`weight = 1 + 0.5*ln(1+access_count)`（保留 3 位小数）。`load` 时按权重降序挑选，超预算的低权重条目被跳过（不会把最常用的挤出去）。 |
| ③ Git 式版本：会话结束提交快照，记忆改写后可 diff/回滚 | `ctx_snapshot`（commit_hash / parent_hash / message）+ `ctx_snapshot_item`（快照时每条 item 的内容快照）。`commit()` 生成链式快照；`diff(c1,c2)` 返回 added/removed/modified（含前后内容）；`rollback(hash)` 用快照内容恢复现存条目、把快照后新增的条目标记 `deleted=1`（不物理删）、并生成一条 `rollback to xxxxxxxx` 提交。 |
| ④ 多 Agent 黑板共享上下文、写入即时可见 | `ctx_blackboard` 按 `room + bkey` 唯一；`bb_put()` 在事务里 `SELECT ... FOR UPDATE` 后 version+1 覆盖，其他 Agent `bb_get()` 立即读到最新版。 |
| ⑤ MCP/Skill 版本更新即时同步、旧版本保留可回滚 | `ctx_resource`（kind=mcp|skill, name, version, payload, content_hash, is_active；唯一键 kind+name+version）。`rs_publish()` 发布新版本自动激活并停用旧版；`rs_versions()` 列全部版本；`rs_rollback(name, ver)` 回滚（旧版本仍保留）；`rs_sync(since)` 返回 `since` 之后有变化的资源激活版本。 |
| ⑥ 文档按章节生成一级/二级摘要，检索先匹配摘要再回读原文 | `ctx_doc` + `ctx_doc_section`（level 1|2、parent_id、title、content、summary）。`doc_import()` 按 `#`/`##` 切分章节，一级章节为父、二级章节 `parent_id` 指向上一个一级；每节用 DeepSeek 生成 ≤140 字摘要（失败截断兜底）。`doc_search()` 标题×3 + 摘要×2 打分排序返回命中；`doc_section(id)` 回读原文。 |

## 二、目录结构

```
context_store/
├── __init__.py          # 包标记
├── schema.sql           # 7 张表 DDL（幂等 CREATE TABLE IF NOT EXISTS）
├── db.py                # pymysql 连接池封装：query/execute/ensure_schema；DB_CONFIG 可用环境变量覆盖
├── store.py             # ContextStore 全部业务逻辑（分层/权重/快照/黑板/资源版本/文档）
├── summarize.py         # DeepSeek 摘要（key 读环境变量 CTX_DEEPSEEK_KEY 或 t_settings.api.key）
└── server.py            # ThreadingHTTPServer :8765，REST + 统一 MCP 工具端点
```

## 三、数据表

| 表 | 关键列 | 说明 |
|----|--------|------|
| ctx_item | room / agent / role / content / layer(L1,L2,L3) / weight / access_count / last_access_at / content_hash / version / deleted | 上下文条目，分层与权重 |
| ctx_snapshot | commit_hash(16) / parent_hash / message / item_count / created_at | 提交快照链 |
| ctx_snapshot_item | commit_hash / item_id / content / version / layer | 快照时内容（用于 diff/rollback） |
| ctx_blackboard | room / bkey / value / version（唯一 room+bkey） | 多 Agent 黑板 |
| ctx_resource | kind(mcp\|skill) / name / version / payload / content_hash / is_active（唯一 kind+name+version） | MCP/Skill 版本库 |
| ctx_doc | name / content_hash / mtime / section_count | 导入的文档 |
| ctx_doc_section | doc_id / parent_id / level(1\|2) / title / content / summary / chapter_order | 章节与摘要 |

## 四、HTTP API

服务地址：`http://127.0.0.1:8765`。所有业务能力同时暴露为 REST 路由与 MCP 统一端点（便于 Java 助手调度）。

### 4.1 统一 MCP 端点

- `GET /api/mcp/tool`：返回 `{ok, ops:[...]}`（工具清单，用于连通性测试）
- `POST /api/mcp/tool`：body `{"op":"context_load","room":"default",...}` → `{ok:true, result:{...}}`；失败 `{ok:false, error:"..."}`

op 一览：`context_append`、`context_load`、`context_sink`、`context_promote`、`context_stats`、`snapshot_commit`、`snapshot_log`、`snapshot_diff`、`snapshot_rollback`、`blackboard_put`、`blackboard_get`、`blackboard_list`、`resource_publish`、`resource_versions`、`resource_rollback`、`resource_sync`、`doc_import`、`doc_search`、`doc_section`、`doc_list`。

### 4.2 主要 REST 路由

| 方法 | 路由 | 说明 |
|------|------|------|
| GET | /health | 健康检查（建表 + 返回 7 张表 + op 数） |
| POST | /shutdown | 关闭服务（仅本机；供 Java 后端「关闭后端服务」联动 8765） |
| POST | /context/append | 追加一条（room/agent/role/content） |
| GET | /context/load?room=&budget=&include_cold= | 按预算载入 L1/L2（可选 L3），返回 used_chars |
| POST | /context/sink | 按容量下沉（l1_cap/l2_cap） |
| POST | /context/promote | 指定条目提升到 L1 并 access_count+1 |
| GET | /context/stats?room= | 各层条数/字符数/权重和 |
| POST | /snapshot/commit、GET /snapshot/log、GET /snapshot/diff、POST /snapshot/rollback | 快照与版本回滚 |
| POST | /blackboard/put、GET /blackboard/get、GET /blackboard/list | 多 Agent 黑板 |
| POST | /resource/publish、GET /resource/versions、POST /resource/rollback、GET /resource/sync | MCP/Skill 版本 |
| POST | /doc/import、GET /doc/search、GET /doc/section、GET /doc/list | 文档分章摘要检索 |

## 五、启动与部署

```bash
# 1) 安装依赖（一次性）
E:\python\.venv\Scripts\python.exe -m pip install pymysql

# 2) 启动服务（后台）
cd /d D:\jvav\farming
E:\python\.venv\Scripts\python.exe -m context_store.server --port 8765 > logs\ctx_server.log 2>&1

# 3) 健康检查
curl http://127.0.0.1:8765/health
```

- 数据库复用主库 `farming_harness`（默认 root，密码由环境变量 `DB_PASSWORD` / `CTX_DB_PASSWORD` 提供），可用环境变量 `CTX_DB_HOST/PORT/USER/PASSWORD/NAME` 覆盖。
- 摘要 Key 取环境变量 `CTX_DEEPSEEK_KEY`，否则读 `t_settings` 的 `api.key`；两者都不可用时摘要退化为正文前 140 字。
- 端口默认 8765，可用 `--port` 指定。

## 六、与 Java 助手的集成

1. `src/main/resources/openclaw/mcp.json` 内置 `context-store`（http，endpoint `http://127.0.0.1:8765/api/mcp/tool`）。
2. 设置页「导入内置 MCP 库」→ 导入后 MCP 列表出现 `上下文存储`，测试连通返回 HTTP 200。
3. `ToolScheduler` 已支持按需求自动调度 context-store 的 op（`context_load/append`、`blackboard_put/get`、`snapshot_commit/rollback`、`doc_search/doc_read`）。
4. 手工联调示例（Java 助手已有 MCP 调用通道）：

```bash
curl -X POST http://127.0.0.1:8080/api/assistant/confirm -H "Content-Type: application/json" \
  -d '{"endpoint":"http://127.0.0.1:8765/api/mcp/tool","args":"{\"op\":\"context_load\",\"room\":\"mcp_demo\",\"budget\":4000}"}'
```

## 七、验收（test_suite/test_f13_context_store.py，40/40 PASS）

- **A 基础**：`/health` 成功、7 张表全部存在。
- **B 分层权重**：追加 30 条 → `sink(l1_cap=10,l2_cap=5)` 后 L1=10 / L2=5 / L3=15；`load(budget=600)` 实际使用 550 字符且默认不含 L3；`include_cold=True` 时带 L3。`promote` 后条目 L1 计数 2→3、access_count 递增。
- **C 快照版本**：commit 链 parent 正确；diff 的 added/removed/modified 均=1 且含前后内容；rollback 恢复被改条目、隐藏新增条目，log 出现 `rollback to` 提交。
- **D 黑板**：agentA 写 v1 → agentB 立即读到；agentB 写 v2 → agentA 读到 v2。
- **E 资源版本**：publish v1/v2（v2 自动激活）→ versions 2 条 → rollback v1 生效且 v2 仍保留 → sync 返回当前激活版本。
- **F 文档摘要**：导入 4 章节（二级 parent 指向正确）→ 摘要非空 → 搜索"三级存储"命中摘要（score=3）→ 回读原文（38 字，摘要 47 字）。

## 八、限制与后续

- 摘要生成依赖 DeepSeek 可用性；不可用时退化为截断，检索质量略降。
- 当前 `load` 按权重+时间挑选，未做同房间向量检索；文档检索为关键词打分（标题/摘要），如需语义检索可在 `doc_search` 前接 embedding。
- 快照按全量 item 复制，条目量极大时可改为增量存储。
- 服务需与 Java 应用一起常驻；Java 侧导入为「内置 MCP」条目，可随时在 MCP 页面停用/启用。
